About Me

Hello! I am Patrick Gorzsás, and I am currently studying game programming at Futuregames in Umeå, Sweden. I have had an interest in games since a very young age. I remember being amazed watching my father play World of Warcraft and Diablo, and over the years that interest has developed into a passion for game development, and in particular game programming.


I first got introduced to game programming by my father when I was around ten years old, through the visual programming language of Scratch 2. Since that day, I have learned many programming languages, game engines, tools and development techniques. Through Futuregames, I have also had the opportunity to showcase my skills in several group projects in a more professional setting.


I have a strong, and perhaps unique mindset when it comes to game development. I do not believe a game can, or should even, appeal to everyone. I believe a game is at its best when it stands confidently for what it is, and fully delivers on its mechanics and design. This philosophy is something I have incorporated into many of the projects that I have been a part of, detailed in the coming sections.

My Experience

Languages

I learned C++ as part of my education at Futuregames, and it is currently the language I have the deepest knowledge of. I am very comfortable with using C++ in Unreal Engine 5, but I am also familiar with more low-level memory management and opimization techniques. C++ was the language me and my teammates used to develop Ghost Bureau of Investigation, an online multiplayer puzzle game, and our largest project at Futuregames.

C# is another language I learned during my time at Futuregames, and I have used it across two team projects made in Unity 6: Echoes, a 2.5D speedrunning platformer, and Don't Feed the Ducks, a casual 3D mobile game. I am comfortable with object oriented programming, generic programming, interfaces, assemblies, and many common design patterns.

GDScript is a language I learned on my own, and it was the language I used for all the programming in Beats Sync, my solo rhythm game made in Godot 3. I have explored almost every aspect of the language, and I am confident in using it for any type of game.

I learned Java before starting my education at Futuregames, and I used it to learn how to build user interfaces for various applications. Though I only have limited knowledge of the language, it is very similar to C#, so learning more of it if required would go quickly.

Engines

I learned Unreal Engine 5 at Futuregames through many solo assignments, as well as two team projects. I am comfortable with using the engine's gameplay and animation frameworks, networking features, materials, shaders and post-process effects, widget systems, plugins, and C++ and Blueprint interaction. I also regularly use the engine to create hobby projects outside of my education.

I have used Unity 6 for two team projects at Futuregames: Echoes, and Don't Feed the Ducks. These projects taught me the engine's composition model and component system, mobile development and deployment, and how to structure a project using C# assemblies to reduce compile times. In particular, I have focused on how to use the engine's physics and user interface systems.

I used Godot 3 to build Beats Sync, a solo shader and effects-heavy rhythm game with an in-game level editor. Building it taught me how to design game architecture and tooling myself, including level editing, and saving and loading, especially for file formats that are not natively supported by the engine. I am confident with using both GDScript and C# to develop games in Godot, and I have spent additional effort exploring the engine's control nodes to create all kinds of user interfaces.

Focus Areas

I have always had a particular interest in user interfaces, and what makes them intuitive and pretty. The user experience has been a big part of all of my solo projects, and I have made sure to explore the tools for creating user interfaces in each engine I use. Though I am most comfortable with the widget systems in Unreal Engine 5, I can build almost any kind of user interface in Unity 6 and Godot 3 and 4 as well.

I first learned shader programming through Godot's native shading language during the development of my solo project Beats Sync. Since then, I have also learned shader programming as part of a course at Futuregames, focusing on the material graph in Unreal Engine 5, and how to use it to create various surface and post-process materials. I can implement many common shading techniques, such as triplanar sampling, palette sampling, vertex displacement, and CPU to GPU interaction. Additionally, I have basic knowledge of HLSL and GLSL shaders.

I learned about networking and multiplayer games in Unreal Engine 5 mainly through the Ghost Bureau of Investigation team project that I was a part of at Futuregames. It is my first hands-on experience with multiplayer game development, and how to manage player and game state, set up a lobby system, and implement server travel mechanics. I have also created several smaller multiplayer projects in Scratch 3, using the website's cloud variable system.

Tools

Perforce has been the version control tool of choice for nearly all of my projects at Futuregames. I am familiar with the standard workflow, and can easily work alongside many teammates during a project in both Unreal Engine and Unity.

Git was the version control tool me and my teammates used via GitHub desktop during the development of Terminal blonde, our final team project at Futuregames. Additionally, I have used git for a small test project in Godot to familiarize myself more with the tool's features and workflow.

I use blender regularly to create 3D assets for my hobby projects, whether it be rigged characters with animations, or simple static objects. I am familiar with box and subdivision modeling, rigging, animation, texture painting, UV-mapping, compositing and the shader graph.

Inkscape is my tool of choice for creating any 2D graphics, whether it be for game assets or user interfaces. I am familiar with a large portion of the tools in the software, and used it for a majority of the graphics in my project Beats Sync.

I have used FL Studio, in particular FL Studio 20, for several years. Before settling on game programming, I was set on becoming a musician, so I have explored a majority of the software, and I can create both music and sound effects for games. I have experience with mixing and mastering, most of the stock plugins, and many other professional plugins such as Serum 1 and 2, Addictive Keys, Kontakt, the Ozone 9 series, and most FabFilter plugins.

Terminal Blonde

Unreal Engine 5 ・ C++, Blueprints ・ PC ・ 10 People ・ 4 Weeks

A puzzle game inspired by Scrutinized where you scam people online.

This game was my fourth game project at Futuregames. I took the role as lead programmer, supervising the development of new features and dividing up work between the programming team. I was also responsible for creating most of the user interface for the in-game computer, including things such as desktop icons, windows, and a web browser.

I learned a lot about the widget systems in Unreal Engine 5, and how to create more advanced custom elements, such as custom scroll bars, buttons, and containers. In general, the game is very systems-heavy, so learning how to implement many features in a short amount of time was a key takeaway. Due to the time constraints, I was also forced to familiarize myself with the engine's Blueprint system a lot more, which is a powerful tool I will be sure to continue using in any future projects when possible.

Additionally, this was the first big project I worked on that used Git and GitHub Desktop as the main tools for version control. It was definitely a big change from Perforce, as we never used different branches and the accompanying merging features of Perforce, but I was able to adapt to the new workflow rather quickly.

Ghost Bureau of Investigation

Unreal Engine 5 ・ C++, Blueprints ・ PC ・ 10 People (International) ・ 8 Weeks

A spooky online multiplayer puzzle game. Created with an international team split between Sweden and Poland.

This was my third game project at Futuregames, and it is the biggest one to date. It was also the first time I used Unreal Engine 5 in a more professional team setting. This was a rather unique project, as we had an international team working on the game, so learning how to communicate effectively, and to properly manage tasks was an important part of this project.

This time around, I was mainly a network programmer, implementing the game's lobby system, character selection system, and server travel mechanics, which involved both C++ and Blueprint code. This was definitely the most challenging game project, as I was not familiar with networked games or the replication system in Unreal Engine 5 prior to this point. After finishing the game, however, I felt much more confident, and I had learned a lot.

In particular, my biggest takeaways from this project were figuring out how replicated components, functions, and variables work, and especially the importance of server authority and proper project structuring, so the right data always lives in the right class.

Don't Feed the Ducks

Unity 6 ・ C# ・ Mobile ・ 10 People ・ 4 Weeks

A 3D mobile game about feeding hazardous foods to ducks and watching them mutate.

This is, in my opinion, my best game project at Futuregames. The entire team, both designers and programmers, did an excellent job with their respective tasks, and we ended up with a very cohesive and chill 3D mobile game. My job was implementing player input, which was somewhat challenging due to it being a mobile game, a platform I had never worked with before, the AI and pathfinding systems for the ducks, the duck mutation system, and the physics for the various throwable food items.

My experience from the previous game project was invaluable here, as I was much more comfortable working with Unity, and implementing the relatively complex behaviour of the ducks and their mutations would not have been possible otherwise. A very important takeaway from this project was to not underestimate my teammates, as I worked on a rather large portion of the game by myself, in fear of others not finishing in time. This is something I made sure to keep in mind during the rest of my game projects at Futuregames, and I believe it had a positive outcome.

Echoes

Unity 6 ・ C# ・ PC ・ 8 People ・ 3 Weeks

A 2.5D speedrunning platformer game. The first team project I was a part of at Futuregames.

This is the first team project I have ever been a part of, and I am relatively pleased with how it went. Since I had never worked in a team before, I learned a lot about communication and the importance of keeping track of what everyone is working on, so the development could move forward effectively. This was also the first time I had used any version control tool, in this instance we used Perforce, so there was a rather large learning curve there too.

Luckily, I had already made many platforming games during my time programming in Scratch, so I was fully prepared for this. Despite the innumerable challenges of working in an unfamiliar engine, and with an unfamiliar team, everything worked out in the end, and we ended up with a decently fun, although somewhat short, playable game.

Beats Sync

Godot 3 ・ GDScript ・ PC ・ Solo ・ 4 Months

A 2D shader and effects-heavy rhythm game inspired by Thumper and Piano Tiles 2.

This is actually the project I am the most proud of. It was my graduation project at the end of upper secondary school, and it was also my first time using a game engine and writing shader code. This project is a combination of three things that have had a huge influence on my life.

First of all, I am a big fan of the rhythm game Thumper, released by Drool. Not only is the gameplay and design fantastic, but it was developed by just two people, only one of whom is a programmer, and it was built in a completely custom engine. Secondly, I took inspiration from Piano Tiles 2, a very famous mobile rhythm game, which I actually held multiple world records for in the past. And finally, I am a huge fan of the very specific gritty, energetic, but still emotional vibe of the hardstyle music genre, specifically between the years of 2010 to 2015. It is something that can not really be described or compared to anything else.

I wanted to combine these three elements into one game that represents me as a person, and I truly think that this is as close as I could have gotten with the time I had. I learned so much about game architecture, shaders, save and load systems, tooling, level editors, and programming as a whole through building this project.

However, the game is still technically a prototype, as there are areas of the level editor that are not entirely finished, and there is only one built-in level. The game was also supposed to be 3D, just like thumper, but I had to settle for 2D, as I knew too little about programming to be able to create something in 3D at the time. Due to these factors, there is no public playable version of the game yet, as this is a project that I am very passionate about, and I want to do it justice by releasing a proper version, the way the game was originally envisioned, once I finish it.

NES Tetris

Scratch 3 ・ GDScript ・ PC ・ Solo ・ 6 Months

A recreation of NES Tetris, reproducing the original game's exact mechanics.

This was the project that really made me want to pursue game programming as a career. The feeling of figuring out exactly how something works, and why it works in that way, is something I enjoy a lot. I had to do research on every part of the original game, and how all the assembly instructions for the NES console's processor work, in order to be able to faithfully recreate it. Every feature, and every bug from the original game, is present here.

I also drew every texture, and recreated every animation by hand, through watching youtube videos, and studying online wikis. The result is, to my knowledge, the only truly accurate recreation of Tetris on the Scratch website to date, which is something I am incredibly proud of. As a bonus, I also added in many of the most popular Game Genie codes as toggleable settings into the game.

However, after having finished the coding, I still did not feel that the project was completely finished. I had been interested in competitive classic Tetris for a long time, so as a long-running side project spanning roughly 4 years, I attempted to reach the maximum possible score on my version of the game. After roughly 800 hours of playtime, I finally reached 999,999 points on August 4th, 2026, marking the true end of this project.
